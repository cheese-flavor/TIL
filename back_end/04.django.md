> Cookie & session
```
쿠키: 서버가 사용자의 웹 브라우저에 전송하는 작은 데이터 조각
      클라 측에서 저장되는 작은데이터 파일 -> 사용자 인증, 추적, 상태 유지 등

사용원리: 브라우저는 쿠키를 key-value 형식으로 저장
        동일한 서버에 재요청시 저장된 쿠키 전송
        두 요청이 동일한 브라우저에서 들어왔는지 아닌지에도 활용

사용목적: 세션관리 - 정보 관리
         개인화 - 사용자 선호, 테마 등 설정
         트래킹 - 사용자 행동을 기록 및 분석


세션: 서버측에서 생성되어 클라 - 서버 간의 상태 유지, 정보저장 방식
     -> 쿠키에 세션 데이터를 저장하여 매 요청마다 응답

     작동원리 = 로그인 하면 session 데이터 생성 및 저장
               인증할 수 있는 session id 발급 -> 클라 응답
               클라에서 session id 저장
               클라에 동일한 서버 접속시 쿠키를 서버에 전달
               요청대마다 함께 전송되어 로그인을 확인함

장고는 세션 자체를 기본값으로 작용해서 진행
```

> 인증
```
인증이 먼저 진행되고 권한이
인증은 항상 view 함수 시작시, 권한 및 제한 확인이 발생하기 전, 다른 코드의 진행이 허용되기 전에 실행됨
인증 자체로는 들어오는 요청을 허용하거나 거부할 수 없으며, 단순히 요청에 사용된 자격증명한 식별


승인되지 않은 응답 및 금지된 응답
1. http 401 - 누구인지 증명자료 x
2. http 403 - 서버 요청이 전달됐지만, 권한땜에 거절


세션 대신 토큰 인증을 사용하는 이유
- 세션 기반 인증은 저장방식 -> 사용자 상태 유지 대문에 서부 부하
- 토큰 기반 인증은 RESTful한 방식으로 클라-서버간 독립성
```
