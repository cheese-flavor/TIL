## Django ##

### web application ###
```
개발: sw 프로그램 구축 / 현재는 멀티기능이 포함된
웹의 동작방식: 클라(요청) <-> 서버(응답) (requests / response)

WEB Framework:  웹 app 빠르게 개발 도와주는 도구
Django: 파이썬 기반 웹 프레임워크 / 백엔드 프론트 함께 / 제공기능 많음 - 커스텀 어려움

MVC 디자인 패턴: MODEL         VIEW          CONTROLLER
               데이터     사용자 인터페이스    비즈니스 로직 
                - APP 구조화 대표 패턴
                - 시각적 요소와 뒤에서 실행되는 로직을 서로 영향없이 독립적이고 쉽게 유지 보수

MTV 디자인 패턴: MODEL         VIEW           TEMPLATE
               데이터          로직           인터페이스
                - VIEW -> TEMPLATE / CONTROLLER -> VIEW  (개발자 입장에서)

```

### REST API ###
```
API: 두 SW가 서로 통신할 수 있게 하는 메커니즘 (요청-응답)
WEB API는 OPEN API 활용 추세 / 웹서버 브라우저 목적

REST: api 서버를 개발하기 위한 일종의 sw 설계 방법론
      -> 모두가 구조가 다르니까 규칙을 만들자

RESTful API: 자원을 정의하고 자원에 대한 주소를 지정 방법?
             REST 원리를 따르면 RESTful이라고 부름

             자원의 식별: url
             자원의 행위: http methods -> get post
             자원의 

url: 통합자원위치
     - 맨 첫부분은 어떤 규약을  http(s)://
     - 도메인 네임
     - port 번호 / 기술적인 문
     - path 웹서버의 경로 ## 중요

Http request methods
     - get: 요청 -> 검색
     - post: 데이터를 리소스 제출, 서버 상태 변경  (get 다른 주소)
     - put: 요청한 주소 리소스 수정
     - delete: 지정된 요수 삭제

Http response status codes
     - 특정 http 요청이 성공적으로 완료되었는지 여부
     - 200번대 성공 / 400번대 클라 에러 / 500번대 서버에러

DRF -> RESFUL API 쉽고 빠르게 설치도와줌
```

### 요청과 응답 ### 
```
요청(urls.py) -> 실행함수(views.py) -> data(modles.py)
```

### 기본 구조 코드 ###

```비유로 이해하기: 우편 시스템
프로젝트 urls.py = 아파트 단지 정문 경비실 (어느 동으로 보낼지 큰 방향만 결정)
앱 urls.py = 각 동의 우편함 관리인 (동 안에서 몇 호실인지 세부 결정)
views.py = 실제 편지를 받는 사람 (요청을 처리해서 응답을 돌려줌)
```

> urls.py
``` urls.py
프로젝트 urls.py = 아파트 단지 정문 경비실 (어느 동으로 보낼지 큰 방향만 결정)
앱 urls.py = 각 동의 우편함 관리인 (동 안에서 몇 호실인지 세부 결정)
-> 최상위 프젝 URL에는 
-> 경로 파일에서는 정말 경로만 진행

from django.urls import path, include   # 하위 주소를 끌어올 때  
from . import views                     # 같은폴더에 있는 파일 전체 '.'

urlpatterns = [                  # 반드시 이 이름으로 찾는 리스트
    path('hello/', views.hello), # hello/ 라는 경로로 요청이 오면 views.hello를 실행하라
    path('my_app/', include('my_app.urls')) # 하위 URL 가져오기
]



path( route, view , name = name) 세가지 인자
    - route = url 문자열('hello/', '/user/<int:id/') #변수도 가능
    - view = 실행할 함수
    - name = 역참조용 / 아직 안쓸듯?
```

### 추가적인 세팅 ###
```
#1. 실제 데이터 views에 집어넣기
from rest_framework.decorators import api_view
from rest_framework.response import Response #알아서 json

@api_view(['GET']) # 요청모드
def menu_list(request):  # 요청에 따른
    menus = [
        {"name": "Espresso", "price": 3000},
        {"name": "Americano", "price": 3500},
        {"name": "Latte", "price": 4000},
    ]
    return Response(menus) #응답 리턴 함수형태로


#2. 앱파일에도 경로 파일을 생성 (views 주소 가져오기)

from . import views (views에서 가져올꺼니까)
from django.urls import path, include  (그냥 경로 기본구조!)

ulpatterns = [
    path('', views.menus_list) #빈문자열 (주소 과제 결과값과 동일하게 만들기)
]
-> views.리스트

#3. 최상위 urls 폴더에 앱 새로 등록 (앱 주소 가져오기)
```
