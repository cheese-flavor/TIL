> 토큰화와 임베딩
```
토큰화: 한번에 이해를 못하니까 단위수준으로 쪼개자 (띄어쓰기 기준은 x)

      -2단계(임베딩): 나누어진 각 토큰에 고유한 숫자를 붙이기 -> 벡터(좌표)로 쓰니까

     단어단위로 쪼개면 가장 직관적 -> but 세상 모든 단어 학습 불가

     서브워드토큰화(BPE): 단어로 구분했는데, 가장 자주 붙은애들끼리 합쳐서
          -> wordpiece = 자주 붙은애들끼리로 했을때 계산이 높아지나?

임베딩: 컴퓨터가 이해할 수 있도록 좌표로 바꾸는 기술
       비슷한 의미를 가진 단어끼리 가깝게 모이게 하는

```

             백터 공간 관점 -> 원소 1 하나와 나머지 0인 형태

문제점: 검색 쿼리 벡터와 대상이 되는 문서 벡터들이 서로 직교, 유사도 측정 x
       1. 차원의 저주: 고차원의 희소벡터를 다루려면 많은 메모리 필요 / 차원 up 데이터 희소
       2. 의미적 정보부족: 비슷한 단어라도 유사 백터로 표현 x

```

> 워드 임베딩
```

           실수 형태로 나타나며 이를 dense라고 부름

대표 기법: word2vec = 비슷한 분포에서 등장하는 단어들은 비슷한 벡터 위치에 놓인다
          CBOW: 주변단어 통해 중심단어 예측 -> 학습속도 UP, 자주나오면 강함 / 희귀단어에 약함
          skip-gram: 중심단어를 통해 주변 단어 예측 -> 적은데이터, 희귀단어에 강함 / 학습속도가 느리다 
          (주변을 계속하니까)

```

> RNN
```
전통적인 MLP: 고정된 길이의 입력을 받아 가변 길이의 데이터를 처리하기에 적합 X

RNN: 가변길이의 입력 가능, 이전 입력 기억을 통해 순차적 데이터 처리 적합
     과거의 정보를 기억하고, 기억한 정보를 활용해 현재의 데이터를 해석
          과거 CELL    ->  새 정보값과 결합  =>  데이터 해석 
     
     입력 가중치: 입력 데이터의 영향력
     순환 가중치: 이전 기억의 영향력
     출력 가중치: 출력 데이터의 영향력 

     한번에 하나의 요소 처리 -> 정보를 앞으로 전달 (각층이 하나의 시점을 나타내는)


     tanh -> -1 ~ 1사이로 / 단어자체의 부정어가 섞여있으니까 + 기울기 폭발 방지

     hidden state= 이전 시점 정보를 담는 -> recurrence 수식 적용
                   ht = fw(ht-1, xt)

     순전파: 단어를 순서대로 셀 통과하면서 은닉상태 업뎃 -> 최종 예측값 출력
            각문제에 맞는 채점기준에 맞춰 오차 계산
            softmax = 클래스 총합이 1이 되도록, 각 확률을 구함

     역전파: 최종오차의 영향력을 역순으로 추적, 가중치가 오차에 미친 영향력을 구함
            

RNN의 한계: 기울기 소실
     - 딥러닝에서 역전파 시 앞쪽 층의 기울기가 0에 가까워져서 장기 의존성 학습이 어려워지는
     - 역전파 과정에서 작은값들이 계속 곱해질수록 더 작은 기울기 -> 장기적인 학습 불가
```

> LSTM
```
시점 T에서 RNN의 길이가 n인 벡터 hidden state, cell state를 가짐
     - 정보 저장 역할을 하나 더 추가(cell state) => 장기적 기억 목표
       -> 그냥 맥락적으로 저장만 하다보니까 불필요한 정보들이 들어올 수 있음

     독자적인 구조로 gate가 추가됨     
     - Forget gate: 이전 cell state에서 무엇을 버리고 무엇을 유지할지 결정
     - input gate: 새 정보 중 얼마나 cell state에 쓸지 결정
     - output gate: cell state중 hidden에 얼마나 줄지

     매 시점마다 게이트의 각 요소는 열림, 닫힘, 혹은 그 사이의 값으로 설정
     게이트는 동적으로 계산, 현재 입력과 hidden state 문맥에 따라 값 정해짐
     시그모이드의 활용 이유: 흐름을 조절하기에 적합한 범위를 출력
     -> 0: 게이트 완전히 닫기 /  1: 완전히 열어서 다 통과 / 0.5: 정보 50%만 통과

     (이전시점의 단기기억 + 현재 시점의 새 정보) * 각 게이트의 가중치 값

     한계: 입력값에 따른 출력값은 단 1개
```


> 언어모델
```
인간의 두뇌가 자연어를 생성하는 능력 모방 -> 단어 시퀀스 전체에 확률 부여 -> 자연스러움
한 문장의 확률은 각 단어의 조건부 확률들의 곱으로 표현가능
bayes rule = 식을 두 부분으로 쪼개어 번역모델과 언어모델로 나누는 방법
         단어와 구가 어떻게 번역되어야하는지 / 유창하게 표현하는

단점: 구조적 복잡성, 많은 수작업 -> 유지 및 확장에 어려움
```

> seq2seq
```
입력과 출력 길이는 달라질 수 있다 -> 언어마다 어순과 표현단위가 다름
입력을 이해하는 역할과 출력 생성 역할을 동시하기에 힘듬

Encoder = 입력문장에 담긴 정보를 인코딩
Decoder = 인코딩된 정보를 조건으로 하여 타겟 문장을 생성

입력 문장 -> encoder -> Context Vector(학습결과) -> decoder(다른언어로 출력) -> 

어순이 달라도 쓸 수 있듯이 데이터간의 패턴을 스스로 적용
-> 다양한 테스크에 활용 ex: 요약, 대화, 코드생성 -> 하나의 통홥 네트워크 연결

학습 초반에는 모델의 예측 능력이 떨어지기에 불안정
모델이 스스로 예측한 단어 대신 정답 언어를 강제로 넣어서 학습 성능을 높임

토큰 출력 방법:  1. 매 단계마다 k개의 가장 유망한 후보 유지
               2. 후보가 eos에 도달하면 완성된 문장으로 리스트 추가
               3. EOS문장이 충분히

문장이 아무리 길어도 context vector는 고정된 크기 하나뿐 = 똑같은 벡터에 크기 상관없이 다
문장이 길어질수록 초반 정보가 희석/손실됨 -> 번역 품질 저하 (장기의존성 문제)

```


> ATTNENTION -> 어텐션 파트 다시보기
```
디코더가 매 시점마다 인코더의 특정 부분을 다시 들여다 볼 수 있다면?  
-> 내가 어디에 집중해야 쉽고 빠르게 얻어낼 수 있을까?
고정된 context vector 하나가 아니라, 매 출력 시점마다 다른 가중치로 조합된 context vector새로 만들기

문장 상의 정보를 가지고 있으면 -> key vector 

(1)score 계산: 쿼리와 key 유사도를 구함
(2)softmax로 가중변환: 점수를 0~1사이 화귤ㄹ처럼 정규화
(3) 가중합: 가중치로 value들을 섞어서 최종 결과를 만듬


seq2seq의 병목현상을 해결하며 긴 시퀀스에서 정보 손실을 방지함
디코더가 필요한 부분에만 집중할 수 있게 하여 성능을 향상시킴

효과: ​​히든 state로만 번역할 때는 해석하기 어려웠는데 어텐션은 실제 잘 번역되고 있는지 확인이 어느 정도 가능하다


셀프어텐션: 학습이 오래 걸려서 -> 가중치행렬을 기반으로 Q K V 벡터를 만듬
셀프닷 어텐션: 기울기 소실, 한쪽으로 SOFTMAX가 쏠리는것을 방지하기 위해서 제곱근 형태로 스케일링 추가

멀티헤드 어텐션: 서로 다른 헤드를 기반으로 병렬 수행 
     -> 같은 문장을 여려명의 전문가가 각자 다른관점으로 동시에 분석한뒤 의견 종합하는 느낌
     -> 실제로 어떤 헤드가 무엇을 학습할지는 사람이 지정하지 않고 학습과정에서 들어남

```


> Transformer
```
1. self-attention = 장기의존성 (아무리 장기가 되더라도 결국에는)
                  = 병렬화 (순전파, 역전파 모두 시퀀스 길이만큼 단꼐 필요 -> 대규모 비효율)
   attention = 각 단어의 표현을 query로 두고, value 집합으로부터 필요한 정보 불러와 결합
               en - de가 아닌 한 문장 내부에서 적용
   
   장점: 순차적으로 처리해야하는 연산수가 시퀀스 길이에 따라 증가 x
        최대 상호작용 거리 = 0(1) -> 모든 단어가 각 층에서 직접 상호자굥
   
   key, value, vector 기반으로 진행?


   단점: 순서 정보 부재 = 단어 간 유사도만 계산, 순서 고려 x
        -> positional Encoding: 각 단어 위치 i를 나타내는 벡터를 정의해, 단어 임베딩 값에 더해 최종 입력 사용
                - sinusoidal postion encoding: 서로 다른 주기의 사인/코사인 함수 합성
                - Learned Absolute: 위치 벡터를 모두 학습파라미터로 설정해 데이터에 맞춰 최적화
        
        비선형성 부족 = 가중 평균 연산이라는 선형 결합에 불과해서 복잡한 패턴이나 깊은 표현력 x
        -> feed-forward network 추가: 비선형 변환이 없는 한계 -> 출력 벡터에 fc+RelU 등을 추가해서 해결
        
        미래 참조 문제 = 생성안된 미래 단어를 참조하게 됨
        -> attention 스코어를 계산할 때, 미래 단어ㅔ 해당하는 항목을 -무한대로 설정, 계산 수행할때 반영 x


2.Transformer = 문장에서 같은 단어라도 여러 이유로 다른 단어에 주목할 수 있다.

순서가 등록이 안돼서 벡터기반으로 위치값을 지정해서 활용
                하지만 단일 self-attention head로는 한가지 관점에서의 단어간 관계 밖에 파악
                -> 따라서 여러 attention head를 두어 다양한 관점에서 동시 정보 파악
                (문맥적, 시제, 명사)

                residual connection: 깊은 신경만 층은 깊어질수록 학습 어려움 
                                     기존입력과의 차이만 학습
                layer nomalization: 층이 깊어질수록 히든벡터 값들이 학습이 불안정
