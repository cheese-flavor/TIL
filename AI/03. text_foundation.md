추가학습하는 모델의 크기: 특정 규모 이하에서는 효과성이 떨어짐 -> 커야만 지시에 대한 응답 창발성이 가능

언제 추론 및 토큰 생성을 멈추고 응답을 제공?
a: EOS 토큰 생성시 종료 or 사전에 정의된 토큰 수 도달시 종료

디코딩 알고리즘
(1) Greedy: 가장 확률이 높은 다음 토큰 선택
     -장점: 사용성 up / 단점: 직후만 고려해서 최종적으로 최선이 아님
(2) beam search: 확률이 높은 k개의 후보를 동시에 고려 (누적생성확률)
     -장점: 좋은 응답 생성확률이 높음 / 단점: 계산비용이 많이 늘어난다(각 후보마다 진행)
(3) Sampling: 거대 언어 모델이 제공한 확률을 기준으로 랜덤하게 생성
     -장점: 다양한 응답 생성 가능 / 단점: 생성된 응답의 품질이 감소가능
(4) Sampling with Temperature: 하이퍼 파라미터 t를 통해 생성확률분포를 임의로 조작
     -장점: 기존 확률이 높은 응답에 집중 / 더 다양한 응답을 생성
     -단점: 모델 예측시 다양성이 극대화 -> 품질은 불안정
(5) TOP-K Sampling: 확률이 높으 K개의 토큰들 중 랜덤하게 샘플링
     -장점: 품질이 낮은 응답을 생성할 가능성을 줄임 -> 가능성 낮은 단어를 버림
     -단점: 확률 분포의 모양에 상관없이 고정된 k개의 후보군을 고려

> 거대 언어 모델의 평가
```
평가: 구축한 시스템이 실제로 잘 동작하는지를 확인하는 단계
     -> 여러 테스크에서의 성능을 종합적으로 판단

정답이 정해진 경우 -> 예측값과 정답값을 확인후 정확도로 판단

정답이 안정해진 경우
     - 사람이 임의의 정답 작성 -> 이와 예측을 비교
          - 텍스트 유사도를 측정 -> 단어수준에서
          - 벡터 공간에서의 유사도 측정

     - 정답과 무관하게 생성 텍스트 자체의 품질만을 측정
          - 얼마나 문장이 확률적으로 자연스러운지
          - 다음단어가 올 확률 계산

     - 여러가지 측면에서 평가 -> 창의성, 유창성 등
          - LLM-as-judge(or G-Eval): llm으로 측정해보자
               테스크, 평가 텍스트, 평가기준 제공

     - 생성텍스트의 상대적 선호를 평가
          - 실제 유저 피드백을 활용

          1. 위치편향: 특정 위치의 응답을 상대적으로 선호
          2. 길이편향: 품질과 무관하게 길이가 긴 응답을 상대적 선호

```
