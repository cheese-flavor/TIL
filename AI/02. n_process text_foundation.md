> RNN
```
전통적인 MLP: 고정된 길이의 입력을 받아 가변 길이의 데이터를 처리하기에 적합 X

RNN: 가변길이의 입력 가능, 이전 입력 기억을 통해 순차적 데이터 처리 적합
     과거의 정보를 기억하고, 기억한 정보를 활용해 현재의 데이터를 해석
          과거 CELL    ->  새 정보값과 결합  =>  데이터 해석 
     
     입력 가중치: 입력 데이터의 영향력
     순환 가중치: 이전 기억의 영향력
     출력 가중치: 출력 데이터의 영향력 

     한번에 하나의 요소 처리 -> 정보를 앞으로 전달 (각층이 하나의 시점을 나타내는)


     tanh -> -1 ~ 1사이로 / 단어자체의 부정어가 섞여있으니까 + 기울기 폭발 방지

     hidden state= 이전 시점 정보를 담는 -> recurrence 수식 적용
                   ht = fw(ht-1, xt)  -> 처리함수(이전ht, 입력벡터)

     순전파: 단어를 순서대로 셀 통과하면서 은닉상태 업뎃 -> 최종 예측값 출력
            각문제에 맞는 채점기준에 맞춰 오차 계산
            softmax = 클래스 총합이 1이 되도록, 각 확률을 구함

     역전파: 최종오차의 영향력을 역순으로 추적, 가중치가 오차에 미친 영향력을 구함
            

RNN의 한계: 기울기 소실
     - 딥러닝에서 역전파 시 앞쪽 층의 기울기가 0에 가까워져서 장기 의존성 학습이 어려워지는
     - 역전파 과정에서 작은값들이 계속 곱해질수록 더 작은 기울기 -> 장기적인 학습 불가
```

> LSTM
```
시점 T에서 RNN의 길이가 n인 벡터 hidden state, cell state를 가짐
     - 정보 저장 역할을 하나 더 추가(cell state) => 장기적 기억 목표
       -> 그냥 맥락적으로 저장만 하다보니까 불필요한 정보들이 들어올 수 있음

     독자적인 구조로 gate가 추가됨     
     - Forget gate: 이전 cell state에서 무엇을 버리고 무엇을 유지할지 결정
     - input gate: 새 정보 중 얼마나 cell state에 쓸지 결정
     - output gate: cell state중 hidden에 얼마나 줄지

     매 시점마다 게이트의 각 요소는 열림, 닫힘, 혹은 그 사이의 값으로 설정
     게이트는 동적으로 계산, 현재 입력과 hidden state 문맥에 따라 값 정해짐
     시그모이드의 활용 이유: 흐름을 조절하기에 적합한 범위를 출력
     -> 0: 게이트 완전히 닫기 /  1: 완전히 열어서 다 통과 / 0.5: 정보 50%만 통과

     (이전시점의 단기기억 + 현재 시점의 새 정보) * 각 게이트의 가중치 값

     한계: 입력값에 따른 출력값은 단 1개
```


> 언어모델
```

한 문장의 확률은 각 단어의 조건부 확률들의 곱으로 표현가능

n-gram = 연속된 n개의 단어 묶음 -> 등장 빈도에 따라 예측
bayes rule = 식을 두 부분으로 쪼개어 번역모델과 언어모델로 나누는 방법
             단어와 구가 어떻게 번역되어야하는지 / 유창하게 표현하는

단점: 구조적 복잡성, 많은 수작업 -> 유지 및 확장에 어려움

> seq2seq
```
입력과 출력 길이는 달라질 수 있다 -> 언어마다 어순과 표현단위가 다름 (ex: 번역)
입력을 이해하는 역할과 출력 생성 역할을 동시하기에 힘듬 -> 2개의 LSTM을 이용

Encoder = 입력문장에 담긴 정보를 인코딩
Decoder = 인코딩된 정보를 조건으로 하여 타겟 문장을 생성

입력 문장 -> encoder -> Context Vector(학습결과) -> decoder(다른언어로 출력) -> 

어순이 달라도 쓸 수 있듯이 데이터간의 패턴을 스스로 적용
-> 다양한 테스크에 활용 ex: 요약, 대화, 코드생성 -> 하나의 통홥 네트워크 연결

학습 초반에는 모델의 예측 능력이 떨어지기에 불안정
모델이 스스로 예측한 단어 대신 정답 언어를 강제로 넣어서 학습 성능을 높임 (Teacher Forcing)



토큰 출력 방법
Greedy Inference: 각단계에서 확률이 가장 높은단어 선택 / 되돌리기 불가능

beam-search:  1. 매 단계마다 k개의 가장 유망한 후보 유지
              2. 후보가 eos에 도달하면 완성된 문장으로 리스트 추가
              3. EOS문장이 충분히 모이면 탐색 종료 -> 로그 확률 합으로 최종선택

문장이 아무리 길어도 context vector는 고정된 크기 하나뿐 = 똑같은 벡터에 크기 상관없이 다

Bottleneck problem = 입력문장을 하나의 벡터로 요약, 마지막 hs 모든 의미 정보
                     문장이 길어질수록 초반 정보가 희석/손실됨 -> 번역 품질 저하 (장기의존성 문제)

```

```

효과
- NMT: 디코더가 필요한 부분에만 집중할 수 있게 하여 성능을 향상시킴
- 병목해결: seq2seq의 병목현상을 해결하며 긴 시퀀스에서 정보 손실을 방지함
- vanishing Gradient 해결: 멀리 떨어진 단어도 직접 연결
​​- 해석가능성: 실제 잘 번역되고 있는지 확인이 어느 정도 가능 -> 의사결정 과정 해석 단서
- 정렬: 필요단어를 자동으로 집중 -> 단어와 단어간의 매핑 관계를 자연스럽게 학습

문장 상의 정보를 가지고 있으면 -> key vector 
decoder(query)와 encoder(values) 관계
(1) score 계산: 쿼리와 key 유사도를 구함
(2) softmax로 가중변환: 점수를 0~1사이 화귤ㄹ처럼 정규화
(3) 가중합: 가중치로 value들을 섞어서 최종 결과를 만듬


self-attention  #그냥 attention이랑 self랑 차이가 머지?
  = 장기 의존성을 효율적으로 포착하고 병렬처리를 가능하게 하는 메커니즘

  rnn의 한계점
  -장기의존성: 시퀀스 길이만큼의 단계를 거치면 학습 힘듬
  -병렬화: forward와 backward pass 모두 시퀀스 길이만큼 단계 필요 / 순차성 -> 병렬 x

  attention: 각 단어 표현 query로 두고, value 집합으로부터 필요 정보 불러와서 결합
             이러한 메커니즘을 encoder-decoder 간이 아니라 문장 내부에서 적용?

  장점: 순차적으로 처리해야하는 연산수가 시퀀스 길이에 따라 증가 x
       최대 상호작용 거리 = 0(1) -> 모든 단어가 각 층에서 직접 상호자굥
   
  각 단어 i를 표현하는 query, key, value 벡터 기반으로 진행 / key가 추가
  query = 단어 i가 다른 단어로부터 어떤 정보를 찾을지를 정의
  key = 단어 i가 자신이 가진 정보의 특성을 표현
  value = 실제로 참조되는 정보 내용
  

  한계: 순서 정보 부재 = 단어 간 유사도만 계산, 순서 고려 x
        -> positional Encoding: 각 단어 위치 i를 나타내는 벡터를 정의해, 단어 임베딩 값에 더해 최종 입력 사용

> Transformer
```
Transformer = encoder-decoder 구조로 설계된 신경망 모델 / decoder가 언어모델과 같은 방식

multi-headed attetion: 문장에서 같은 단어라도 여러 이유로 다른단어에 주목 가능
                       self에서는 한가지 관점 -> 다양한 관점을 위해 (문맥, 시제, 명사)

scaled Dot Product = 이거 해야되나?

residual connection: 깊은 신경만 층은 깊어질수록 학습 어려움, 기존입력과의 차이만 학습
layer normalization: 층이 깊어질수록 히든벡터 값들이 학습이 불안정, 정규화를 통해 안전성과 빠르게
Decoder: 여러개 decoder 블록 / 단방향 문맥만 활용 / cross-attention 수행
         - Masked self-attention: 미래 단어 안보도록
         - add&norm: residual connection + layer normalization
         - Feed-ForwardNetwork: 각 위치 비선형 변환 수행
         - add&norm: residual connection + layer normalization
         *encoder 출력 표현 참조 / query는 decoder에서, key와 value는 encoder에서 가져옴

Encoder: transformer의 encoder는 양방향 문맥 모두 활용
         입력 문장을 의미적 표현으로 변환, 양방향 문맥
         *decoder와 diff = masking 제거 

pretraning: 최신모델 성능향상을 위한 사전학습 결합
```

> 사전학습
```
사전학습: 대규모 데이터셋을 이용해, 모델이 데이터의 일반적인 특징과 표현을 학습하도록 하는 과정(비지도)

해당관점에서
워드임베딩: 다운스트림 태스크(데이터양 적음 문제), 학습효율이 낮고, 많은 데이터와 시간 필요
언어모델: 언어에 대한 표현 학습, 파라미터 초기화관점에서 효과적, 확률분포학습을 통해 샘플링 생성
         사전학습 기반으로 언어패턴이 잘 학습된 파라미터로 초기화


Encoder 모델
양방향모델 -> 입력단어 일부를 mask 토큰으로 치환, 이 mask자리에 올 단어 예측

BERT
학습방법1 Masked LM: 입력토큰 15% 무작위 선택 -> MASK 치환과 랜덤 적용

> 거대언어모델의 추론
```
거대언어모델의 자동회귀 생성= 순차적 추론을 통한 토큰별 생성

언제 추론 및 토큰 생성을 멈추고 응답을 제공?
a: EOS 토큰 생성시 종료 or 사전에 정의된 토큰 수 도달시 종료

디코딩 알고리즘
(1) Greedy: 가장 확률이 높은 다음 토큰 선택
     -장점: 사용성 up / 단점: 직후만 고려해서 최종적으로 최선이 아님

(2) beam search: 확률이 높은 k개의 후보를 동시에 고려 (누적생성확률)
     -장점: 좋은 응답 생성확률이 높음 / 단점: 계산비용이 많이 늘어남(각 후보마다 진행)
     
(3) Sampling: 거대 언어 모델이 제공한 확률을 기준으로 랜덤하게 생성
     -장점: 다양한 응답 생성 가능 / 단점: 생성된 응답의 품질이 감소가능

(4) Sampling with Temperature: 하이퍼 파라미터 t를 통해 생성확률분포를 임의로 조작
     -장점: 창의성/안정성 조절 가능
     -단점: t 분포에 따라 (t<1) 다양성 떨어짐 / (t>1) 품질 불안정 

(5) TOP-K Sampling: 확률이 높은 K개의 토큰들 중 랜덤하게 샘플링
     -장점: 품질이 낮은 응답을 생성할 가능성을 줄임 -> 가능성 낮은 단어를 버림
     -단점: 확률 분포의 모양에 상관없이 고정된 k개의 후보군을 고려

(6) TOP-P Sampling: k를 고정하는대신, 누적확률 p에 집중하여 k를 자동으로 조절
     -장점: 확률 누적기준 품질 다양성 균형
     -단점: p값 설정 필요



프롬프트 엔지니어링 = 원하는 답을 얻기 위해 모델에 주어지는 입력을 설계 조정 기법
입력프롬프트 = (1) 지시 (2) 예시 (패턴을 따라가는)

시스템프롬프트= 유저 쿼리와 무관하게 기본값으로 주어지는 llm 입력
              경우에 따라 수정이 불가능 / llm, 개인 메모리에 활용
              -> (환각현상) 시스템프롬프트 내 제약 사항들이 답변에 반영안될수 있음

유저쿼리: 감정분류와 같은 쉬운 문제 뿐만 아니라 거대 언어 모델로 푸는것에 많이 집중

chain of Thought 프롬프팅: 추론 과정도 예시에 포함 -> 성능이 크게 증가
0-shot CoT 프롬프팅: 예시 없이도 추론 성능이 강화가 될까? -> 임계점만 넘으면

     - 사람이 임의의 정답 작성 -> 이와 예측을 비교
          - 텍스트 유사도를 측정 -> 단어수준에서
          - 벡터 공간에서의 유사도 측정

          - 얼마나 문장이 확률적으로 자연스러운지 / 다음 단어 확률 계산

     - llm으로 측정: 여러가지 측면에서 평가 -> 창의성, 유창성 등

          3. 자기선호편향: 생성모델이 평가모델과 같은 경우 이를 선호
