# 16234 인구 이동

- [문제](https://www.acmicpc.net/problem/16234)
- 난이도: Gold IV (계획 기준)
- 결과: BOJ 정답(사용자 보고), 독립 채점 검증 미수행
- [solution.py](solution.py): 채팅 최종 공유본에 문제 정보 주석 추가. 실제 제출 원문 미대조, 재귀 제한 추가 여부 미확인.

## 풀이 접근

- 하루마다 visited 초기화 후 미방문 좌표에서 DFS로 연합 구성.
- 인접 좌표의 인구 차이가 L~R이면 방문 처리 후 동일한 group에 좌표 누적.
- 연합 크기가 2 이상이면 정수 평균으로 재분배하고 possible=True.
- 하루 전체에서 이동이 발생하지 않으면 종료, 발생한 날만 day 증가.
- 연합을 즉시 갱신해도 이미 방문한 영역은 당일 후속 탐색에서 제외되므로 나머지 연합의 판정에 영향 없음.

## 수정 및 복습

- 행 좌표 r과 인구 차이 상한 R을 분리하고 range(c)를 range(n)으로 수정.
- 조건문 여러 줄은 괄호 사용.
- g + [r, c] 대신 g.append((r, c)) 및 동일한 리스트 전달; 영역 DFS에서는 pop/방문 복원 불필요.
- group은 연합마다 초기화. DFS 내부에서 방문 완료하므로 합산 시 중복 방문 처리 제거 가능.
- possible=False로 시작하고 종료 확인 뒤 day 증가.
- 최대 재귀 깊이는 N²=2500; 기본 제한 초과 가능. sys.setrecursionlimit(10000) 추가 권장. 실제 추가 여부 미확인. 반복형 DFS/BFS도 대안.
- 전체 호출 횟수와 동시에 중첩된 호출 깊이를 구분.

## 복잡도

- D일 이동 시 시간 O((D+1)N²), 공간 O(N²).

## 검증용 반례 (기대값, 실행 미검증)

- 이동 없음: 2 40 50 / 50 30 / 20 40 → 0.
- 이동 1회: 2 20 50 / 50 30 / 20 40 → 1.
- 최대 깊이 점검: 50×50 격자에 1과 2를 번갈아 배치, L=R=1 → 1. 재귀 제한 점검 필요.
- 재풀이 날짜: 미정.
