## 문제 핵심과 접근

- `N`개 식당마다 **검사팀장 정확히 1명 필수**
- 검사팀장 1명이 검사할 수 있는 최대 인원 `tl`, 검사팀원 1명이 검사할 수 있는 최대 인원 `tm`
- 각 식당의 고객 수에서 팀장 검사량을 제외하고 **남은 고객이 양수인 경우에만** 검사팀원 배치
- 필요한 팀원 수는 `ceil((고객 수 - tl) / tm)`의 음수가 아닌 값. 총 검사자 수는 팀장 `N`명 + 모든 식당의 팀원 수

## 1차 실패 코드 분석

1차 코드는 식당별로 무조건 `p = people[i] - tl` 계산 후 `p // tm`과 `p % tm`으로 팀원 수를 더하는 방식.

- 누락된 조건 · **고객 수가 팀장 최대 처리량보다 작은 식당**
- `p`가 음수여도 Python의 정수 나눗셈과 나머지 연산이 실행되어 **음수 팀원 수**를 결과에 합산할 수 있음
- 코드트리 히든 케이스의 정확한 입력은 알 수 없음. 다음 입력은 같은 버그를 재현하는 **별도 구성한 최소 반례**

```text
입력
1
1
5 2

기대 출력
1

1차 코드 출력
-1
```

- 첫 식당 고객 1명, 팀장 최대 5명이므로 팀장 1명으로 충분
- 1차 코드의 `p = -4`, `p % 2 = 0`, `p // 2 = -2`, 최종 `-2 + 1 = -1` 출력
- 증상 · 팀원 수가 0보다 작아짐. **정상적인 팀원 수는 0 이상이어야 한다는 불변 조건 위반**

## 2차 정답 코드 검토

- `if people[i] < tl: continue`로 팀장만 필요한 식당을 먼저 건너뜀
- `people[i] == tl`인 경우도 `p = 0`이 되어 팀원 0명 추가하므로 정답. 의도를 드러내려면 `<= tl`로 작성 가능
- 남은 고객이 팀원의 처리량으로 정확히 나누어떨어지면 몫만, 아니면 팀원 1명 추가
- 팀장 `N`명은 마지막 `sum_p + n`에서 일괄 계산
- **시간 복잡도 O(N)** · 식당 수만큼 순회
- **공간 복잡도 O(N)** · `people` 리스트 저장. 반복문 내 추가 사용 공간은 `O(1)`

## 경계 조건 점검

| 상황 | 예시 (고객, tl, tm) | 필요 인원(해당 식당) | 확인 |
| --- | --- | --- | --- |
| 팀장이 모두 검사 가능 | `(1, 5, 2)` | 1명 | 1차 실패 원인 |
| 팀장 처리량과 정확히 같음 | `(5, 5, 2)` | 1명 | 2차의 `<` 조건에서도 정상 |
| 잔여 인원이 팀원 처리량보다 작음 | `(6, 5, 2)` | 2명 | 팀원 올림 |
| 나누어떨어지는 잔여 인원 | `(9, 5, 2)` | 3명 | 불필요한 팀원 방지 |
| 여러 식당의 팀장 필수 배치 | `[1, 6, 9], tl=5, tm=2` | 총 6명 | 식당별 1명 + 팀원 3명 |

## 코드 개선 제안 (미제출, 원본 미변경)

조건을 빠뜨리지 않도록 잔여 고객 수를 명시적으로 0 이상으로 유지하고 정수 연산으로 올림 처리 가능.

```python
n = int(input())
people = list(map(int, input().split()))
tl, tm = map(int, input().split())

answer = n  # 식당마다 팀장 1명 필수
for customers in people:
    remaining = max(0, customers - tl)
    answer += (remaining + tm - 1) // tm  # tm > 0
print(answer)
```

- `max(0, ...)`은 음수 잔여 인원 방지, `(x + d - 1) // d`는 비음수 정수 `x`, 양의 정수 `d`에 대한 올림 나눗셈
- `tm > 0`은 문제의 정상 입력 제약을 전제로 함
- **검증 구분:** 코드트리 2차 정답 확인은 사용자 보고. 위 반례와 개선 코드는 코드 리뷰용으로 작성했으며 별도 코드트리 채점 기록을 주장하지 않음
